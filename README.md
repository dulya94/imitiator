# PC Action Imitator

Desktop-приложение для **Windows 11**: записывает действия пользователя (мышь + клавиатура)
и воспроизводит их вручную, по горячей клавише или по расписанию (в том числе,
когда пользователя нет за компьютером).

---

## Возможности

- 🔴 **Запись**: движения и клики мыши, прокрутка, нажатия клавиш — с точными
  временными метками (`time.time()` относительно старта записи).
- ▶️ **Воспроизведение**: плавное, с сохранением реальных таймингов событий
  (ожидание по `time.perf_counter()`, шаг ~20 мс; длинные перемещения мыши
  интерполируются). Работает в фоновом потоке — UI не блокируется.
- 🔁 **Цикл**, ⏱ **задержка перед стартом**, ⏰ **расписание**:
  - «Каждый день в…» (например, 10:00),
  - «Каждые N минут»,
  - «Когда ПК без действий» — запуск при простое ввода дольше X секунд
    (WinAPI `GetLastInputInfo`, срабатывает независимо от фокуса окон).
- ✏ **Переименование**, 🗑 **удаление**, 📄 список сценариев с длительностью и датой.
- 💬 **Подсказки при наведении** на кнопки — с описанием и горячими клавишами
  (F9/F10/ESC), включая контекстные подсказки главной кнопки в режиме записи.
- ⌨ **Глобальные горячие клавиши** (работают без фокуса окна):

| Клавиша | Действие |
|---------|----------|
| **F9**  | старт записи нового сценария (имя назначается автоматически) |
| **F10** | стоп записи |
| **ESC** | стоп воспроизведения (failsafe) |

- 💾 **Хранение**: сценарии — `/scenarios/<имя>.json`, настройки — `/config.json`.
  Запись файлов атомарная (`*.tmp` → `os.replace`), повреждённые JSON не ломают список.

## Установка и запуск

```powershell
# 1. Установите Python 3.10+ с python.org (галочка "tcl/tk" включена по умолчанию)

# 2. Перейдите в папку проекта
cd PCActionImitator

# 3. Установите зависимости
python -m pip install -r requirements.txt

# 4. Запустите приложение
python main.py
```

> 💡 Рекомендуется запускать **от имени администратора**: перехват ввода
> `pynput` не работает для окон с повышенными привилегиями (UAC), если само
> приложение запущено без них.

### Автозапуск с Windows (опционально)

Создайте ярлык `python main.py` и поместите его в папку
`shell:startup` (`Win+R` → `shell:startup`).

## Как пользоваться

1. Нажмите **«＋ Добавить имитацию работы»** (или **F9**), введите имя сценария.
2. Выполните нужные действия — они записываются.
3. Остановите запись (**F10** или красная кнопка сверху). Сценарий сохранится
   в `scenarios/<имя>.json` и появится в списке.
4. Нажмите **▶** в строке сценария (или **ESC** в любой момент для остановки).
5. Клик по строке списка **выбирает** сценарий — настройки внизу
   (цикл, задержка, расписание) применяются к нему через кнопку
   «Применить к выбранному».

### Переключение стендов

**Стенд, на котором запускается имитация, задаётся в списке «Стенд действий».**

- В выпадающем списке уже есть 4 предустановленных стенда:
  1. `https://portal.dev.symphony.itfb.tech/`
  2. `https://portal.test.symphony.itfb.tech/`
  3. `https://portal.demo.symphony.itfb.tech/`
  4. `https://portal.dev.symphony.moek.itfb.tech/`
- Чтобы сменить стенд — просто выберите его в списке (или впишите свою
  ссылку и нажмите **Enter**/**🌐 Открыть**). Выбор **сразу запоминается**
  и применяется к последующим запускам, в том числе **по расписанию**.
- Кнопка **«＋ Стенд»** («Добавить стенд для имитации») — введите ссылку на
  новый стенд: он добавится в список, станет текущим, при желании сразу
  откроется в браузере. Список стендов (`stands`) хранится в `config.json`.
- Кнопка **🔗** в строке сценария — задать **свой стенд именно для этого
  сценария** (в подписи строки появится `🌐 <url>`; пусто = использовать
  стенд, выбранный в списке).

**Куда идёт запуск ▶:** по умолчанию — на стенд, **выбранный в списке**
«Стенд действий» (его можно менять в любой момент, даже если у сценария
сохранён свой адрес при записи). Если включить галочку
**«Для запуска брать стенд из сценария (🔗), если он задан»** — приоритет
получит адрес, сохранённый в сценарии (кнопка 🔗), а при его отсутствии
снова используется выбранный в списке.

## Пример JSON сценария

```json
{
  "schema": 1,
  "name": "example_scenario",
  "created_at": 1789098000.0,
  "duration": 5.6,
  "url": "https://portal.dev.symphony.itfb.tech/document-and-storage/list/all",
  "screen_w": 1920,
  "screen_h": 1080,
  "events": [
    { "type": "move",  "t": 0.0,  "x": 400, "y": 300 },
    { "type": "click", "t": 1.2,  "x": 705, "y": 438, "button": "left", "pressed": true },
    { "type": "click", "t": 1.28, "x": 705, "y": 438, "button": "left", "pressed": false },
    { "type": "key",   "t": 2.0,  "key": "c:h", "action": "press" },
    { "type": "key",   "t": 2.1,  "key": "c:h", "action": "release" },
    { "type": "scroll","t": 3.0,  "x": 705, "y": 438, "dx": 0, "dy": -3 },
    { "type": "key",   "t": 4.0,  "key": "k:enter", "action": "press" },
    { "type": "key",   "t": 4.1,  "key": "k:enter", "action": "release" }
  ]
}
```

Формат клавиши: `"c:<char>"` — обычный символ, `"k:<name>"` — специальная
клавиша (например, `k:enter`, `k:esc`, `k:shift`), `"v:<vk>"` — запасной
вариант по виртуальному коду Windows.

### Учёт разрешения экрана

При записи в сценарий сохраняется разрешение экрана (`screen_w`/`screen_h`).
При воспроизведении на другом разрешении (другой монитор, сменённые настройки,
масштаб Windows 125–150%) координаты **пропорционально пересчитываются** под
текущий экран и отсекаются его границами. Поведением управляет чекбокс
**«Подгонять координаты под разрешение экрана»** (ключ `adapt_resolution`
в config.json). Старые сценарии без этих полей воспроизводятся «как записаны».
Процесс приложения DPI-aware (`SetProcessDpiAwarenessContext`), поэтому
координаты совпадают с физическими пикселями при любом масштабе Windows.

### config.json

```json
{
  "loop": false,
  "delay": 0,
  "schedules": {
    "Утренний сценарий": { "mode": "daily", "time": "10:00" }
  }
}
```

## Структура проекта

```
PCActionImitator/
├── main.py                    # точка входа + Tkinter UI
├── models.py                  # Event, Scenario, сериализация клавиш
├── recorder.py                # запись действий (pynput Listener'ы)
├── player.py                  # воспроизведение (фоновый поток, точные тайминги)
├── scheduler.py               # APScheduler + режим простоя ПК (GetLastInputInfo)
├── hotkeys.py                 # F9 / F10 / ESC
├── storage.py                 # /scenarios/*.json + /config.json
├── webtools.py                # целевой сайт, открытие в браузере
├── screeninfo.py              # разрешение экрана, пересчёт координат, DPI-aware
├── requirements.txt
├── README.md
├── config.json                # создаётся автоматически
└── scenarios/
    ├── example_scenario.json  # пример сценария
    └── <имя>.json             # ваши сценарии
```

## Важные замечания

- ⚠️ Приложение выполняет **реальный ввод** в ваши окна. Не оставляйте
  сценарий воспроизводиться с открытыми окнами, где случайные клики/текст
  могут нанести вред (терминалы, редакторы конфигов и т.п.).
- 🛡 Некоторые антивирусы могут реагировать на глобальный перехват ввода
  (`pynput`) — добавьте папку в исключения.
- 🔒 Воспроизведение **не работает** в окнах с повышенными привилегиями и на
  экране блокировки/экране UAC — это ограничение Windows (UIPI).
- ESC воспроизводится «внутри» сценария безопасно: плеер помечает
  синтетические нажатия и failsafe-хоткей их игнорирует.
